DÉMARRER
Node.js 22 ou ultérieur. Dans le dossier du projet :
  npm ci
  npm run build
  npm start
La console indique les URL. Le serveur écoute uniquement 127.0.0.1.
Si le port est occupé, arrêter l’instance précédente avant de relancer.

CONTENU ET CONCEPTION
20 pages et une 404 : accueil, catalogue, quatre soins, présentation,
galerie, FAQ, journal, six articles, contact, sources, mentions et confidentialité.
La recherche documentaire et l’étude de trois concurrents sont dans research/.
Direction proposée : crème, bordeaux, Manrope et Cormorant Garamond,
photographies réelles, composition sobre et adaptée au mobile.
La signature typographique est une proposition, aucun logo officiel n’était fourni.
Réservation exclusivement par téléphone ; le contact propose aussi la copie
du numéro. Adresse, Google Maps à la demande, itinéraires Google Maps,
Waze, Apple Plans et QR code facilitent la venue. Aucun créneau n’est
confirmé en ligne et Fresha n’est pas présenté comme un agenda.

PHOTOGRAPHIES
L’utilisateur a confirmé les droits d’utilisation des photographies pour
ce projet le 11 octobre 2026. Les images sont incluses dans la démo publique.
Le portrait noir et blanc 1080 × 1080 provient de la fiche nominative de
l’École du Kobido. La capture Instagram fournie est conservée intacte ;
ses détails sont cadrés par CSS. Les références figurent dans research/assets.json.
Des originaux HD supplémentaires du portrait souriant, des gestes ou du
cabinet pourraient améliorer la galerie. Leur absence ne remet pas en
attente l’autorisation déjà donnée pour les images utilisées.
media.photosAuthorized vaut true. media.shareImage désigne le portrait HD,
ses dimensions et son texte alternatif pour le partage Open Graph.

RÉFÉRENCEMENT ET JOURNAL
Chaque page dispose d’un titre et d’une description uniques, d’une URL
canonique et de métadonnées de partage. Le graph JSON-LD relie l’établissement,
le site, les pages, les fils d’Ariane, les soins et les articles. Les coordonnées
sont issues du fichier de contenu commun, sans avis, prix ou horaires inventés.
Les six articles ont une catégorie, des sources et des liens vers les soins
concernés. Leur auteur affiché est « Rédaction de la démonstration » ; ils ne
sont pas automatiquement attribués à Nadège. Les dates viennent des contenus.
La stratégie et ses sources Google sont dans research/seo-notes.json.
Ces préparations ne garantissent ni classement ni citation par un moteur de réponse.

ÉDITION ET PUBLICATION
1. Se connecter au back-office local.
2. Modifier l’accueil, les coordonnées, les soins, la présentation, la FAQ,
   les articles ou les pages légales. Les articles disposent de champs pour
   catégorie, dates, sources « Titre | URL » et slugs des soins associés.
   Enregistrer ; les informations malformées sont refusées.
3. Dans Export & publication, générer la preview puis la relire.
4. Marquer la version relue comme validée (validation locale horodatée).
5. Dans le terminal :
     npm test
     npm run build
     npm run check
     git add data/content.json
     git commit -m "Mise à jour des contenus"
     git push
6. Vérifier le succès de Publish public demo dans GitHub Actions.
Le bouton local de génération ne publie pas sur Internet.
L’administration ne fonctionne pas sur GitHub Pages : cet hébergeur sert
uniquement des fichiers statiques. Ne jamais y copier admin/, server.mjs ou .local/.

SAUVEGARDES
Chaque enregistrement/restauration conserve la version précédente dans
.local/history/. L’interface permet une restauration avec contrôle de version.
La relecture et les changements ont une trace locale. Git conserve les versions
publiées. Export JSON disponible ; copier régulièrement ce fichier et une sauvegarde
chiffrée de .local/ sur un support distinct pour résister à une perte de l’ordinateur.
Ces copies externes ne sont pas configurées automatiquement.
