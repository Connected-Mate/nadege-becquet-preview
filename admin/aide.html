Votre site,
en toute autonomie.

Un espace local pour préparer les contenus, conserver leur historique et générer le site à publier.

Où fonctionne cet espace ?

L’administration fonctionne sur l’ordinateur où ce projet est installé, à l’adresse http://127.0.0.1:4173/admin/. Le serveur écoute uniquement sur cet ordinateur. Il faut laisser le terminal ouvert pour l’utiliser.

GitHub Pages héberge le site statique public. L’administration, les mots de passe et l’historique ne sont jamais inclus dans son export. L’URL de démonstration reste publique même avec la directive noindex.

npm run build
npm run start

Première connexion

Le premier démarrage génère un mot de passe aléatoire dans .local/admin-access.txt. Ouvrez ce fichier sur votre ordinateur et copiez le mot de passe dans le formulaire de connexion. Il n’est jamais affiché dans les journaux du serveur.

Rangez le mot de passe dans un gestionnaire de mots de passe. Vous pouvez ensuite supprimer admin-access.txt ; le serveur conserve uniquement son empreinte protégée dans .local/credentials.json.

Si vous perdez le mot de passe, arrêtez le serveur, lancez la commande suivante puis redémarrez-le :

node server.mjs --reset-password
npm run start

Une session expire au bout de huit heures. Après cinq échecs, les connexions sont bloquées pendant quinze minutes.

Modifier et vérifier

  1. Choisissez une rubrique, puis modifiez les champs. L’éditeur « Tous les contenus » donne accès au fichier JSON complet.
  2. Cliquez sur Enregistrer. Les champs sont validés et le contenu précédent est sauvegardé. Un conflit entre deux onglets est signalé pour éviter d’écraser une modification.
  3. Dans Export & publication, cliquez sur Générer la preview.
  4. Ouvrez Voir le site et vérifiez le résultat, y compris sur mobile. Enregistrer un texte ne modifie pas directement le site public.

Pour conserver des liens stables, évitez de modifier les adresses des soins et des articles déjà publiés. Les champs de texte utilisent du texte simple ; conservez les champs complémentaires et sources dans l’éditeur JSON.

Restaurer et sauvegarder

La rubrique Historique permet de restaurer un contenu précédent. La restauration conserve aussi la version actuelle avant de la remplacer. Générez ensuite la preview pour voir le résultat.

Les versions sont stockées dans .local/history/ et le journal des actions dans .local/audit.jsonl. Ces fichiers restent sur cet ordinateur. Une copie locale ne protège pas contre la perte de l’ordinateur : sauvegardez le projet et son dossier .local/ sur un support sûr, avec chiffrement si possible. Ne les publiez jamais dans Git.

Le bouton Exporter les contenus JSON télécharge la dernière version enregistrée. Le dossier dist/ contient le site statique généré.

Publier une modification

Après relecture de la preview, utilisez Valider cette version après relecture dans Export & publication. La date et la version sont inscrites dans le journal local. Une modification de contenu annule cet état pour la nouvelle version. Cette trace de relecture ne certifie pas automatiquement les informations ou les droits.

Depuis un projet dont le dépôt et GitHub Pages sont déjà configurés, utilisez ces commandes après vérification :

npm run build
git add data/content.json
git commit -m "Mise à jour des contenus"
git push

Le workflow GitHub reconstruit et publie le site. Consultez son résultat dans l’onglet Actions du dépôt. La génération locale ne publie rien et ne garantit pas que le déploiement distant a réussi.

Avant le lancement officiel, confirmez les informations de l’entreprise, les droits des visuels, les mentions légales et l’objectif de contact. La date de retrait de la démonstration est un paramètre de préparation ; suivez les instructions de livraison pour son retrait effectif.
